# 暂停、存档、收尾与监控

> 这一篇管：一次运行半路停下或结束以后怎么办——存档怎么存、留多久、怎样接着做，收尾时在 issue 里怎么反馈，以及怎么看到运行过程。谁能叫停、重新打标签时比什么，见 [触发与叫停](触发与叫停.md)。依据见 [调研/会话记录检查点与失败重来](调研/会话记录检查点与失败重来.md)、[调研/Actions平台事实_产物缓存重跑定时](调研/Actions平台事实_产物缓存重跑定时.md)、[调研/监控与运行轨迹](调研/监控与运行轨迹.md)。

## 一、管的是"运行"，不是聊天会话

聊天机器人里的会话管理，是让人隔天回来还能接着聊。RepoAegis 没有这种人：agent 从开工到结束中间没人插话。我们要管的是**运行**：同一个 issue 可能先后有好几次运行，哪次算数、哪次该停，停下的那次能不能接着做，失败了怎么办。agent 和模型之间那段对话怎么管（截断、摘要），归 agent 循环（[agent 怎么干活](agent怎么干活.md)）。

## 二、存档怎么存

agent **每走一步**就把进度写到本机磁盘：改动补丁、对话记录、已用时间、开工时默认分支所在的提交。运行被取消时，GitHub 先给程序发类似 Ctrl-C 的信号，约 10 秒后强制结束；之后写了 `if: cancelled()` 的步骤仍会执行（官方文档 `workflow-cancellation.md`），由这个步骤把磁盘上的进度上传成运行产物。不在收到信号时才存，是因为 10 秒太紧，每步都存就只剩上传一件事。

**被取消后先判断再上传（2026-11-03 定）。** 取消接口不带原因，被取消的运行要自己判断是不是暂停：`if: cancelled()` 的步骤在运行机上（AWF 容器外）查 issue 的事件记录，从自己开工时打标签的那一刻往后，有 Write、Maintain 或 Admin 撤标签或关闭 issue，才算暂停，上传暂停存档；否则直接停、不存档，包括删除或转移 issue（查不到 issue）、内容不同的重新打标签、重新打标签时内容检查没过。没有采用"被取消一律上传、之后按存档名里的内容指纹筛掉"，因为那样会给不该存档的情况留下存档，和[触发与叫停](触发与叫停.md)第五节"删除、转移直接停、不存档"不符。

暂停存档的产物名是 `repoaegis-pause-issue-编号-内容哈希-截止时刻(UTC)`，新的运行只看名字就知道内容是否一致、是否过期，不用下载下来比（[src/repoaegis/checkpoint.py](../src/repoaegis/checkpoint.py)）。机器直接坏掉时磁盘跟着没了，存不下来，只能靠收尾作业说明。

## 三、存档分三类，各留多久（2026-10-27 定）

保留期在上传时用产物的 `retention-days` 设好，到期 GitHub 自动删除，不另写定时清理。

- **暂停存档**：保留到**下一个工作日结束**。例如周四暂停留到周五 23:59，周五暂停留到下周一 23:59，9 月 30 日暂停跳过国庆留到 10 月 8 日 23:59，调休上班的周六算工作日。截止时刻由我们的程序按日历算出，写进存档名和暂停留言；重新打标签时过了截止时刻就当没有存档。产物的保留天数只能是整数，设得刚好盖过这个时刻，作为兜底删除。时区和节假日可配置，默认北京时间、中国大陆的法定节假日和调休。节假日"做个样子就行"（2026-10-27），表里目前只有 2026 年，不承诺每年补；遇到表里没有的年份只按周末算，并在日志里提醒。所以 2026-12-31 暂停时，2027-01-01 会被算成工作日。另外两种情况提前删：内容不一致的重新打标签，以及接着做完以后。
- **出错存档**：超时、token 用满、模型接口一直失败、连续不调工具、产出检查没过、交付失败时留下，用来查原因，以后也可作评测素材。保留 **30 天**，不因重新打标签提前删。
- **完成记录**：正常做完开出 PR 时留下补丁、汇报和对话记录，用来回看"这个 PR 是怎么做出来的"。保留 **30 天**。

项目是试验项目，存档内容公开问题不大（2026-10-27 确认）。要知道的事实：公开仓库里任何登录 GitHub 的人都能下载产物；私有仓库的产物占 500 MB 免费额度（和 Packages 共用）。agent 能碰到的地方没有真密钥（模型钥匙在 AWF 的密钥代理里，只读 GitHub 令牌只给容器外的读 issue 服务），但存档和轨迹里有完整的命令输出，万一混进了密钥会被公开，所以要在写轨迹时遮掉（规则待定，见第八节）。

## 四、接着做时的默认做法（2026-10-27，用户未提异议，按建议执行）

- **60 分钟按累计算**：存档里记着已用时间，接着做时只剩余下的。否则停一下再打上就能绕过上限。
- **主分支在暂停期间有新提交，仍在原来的提交上接着做**：存档里记着那个提交号；PR 和主分支有冲突交给人处理。
- **恢复代码改动和对话记录**，在对话末尾告诉 agent"你在这里被暂停过，机器已经换了，之前装的依赖要重新装"。
- **等旧运行完全停下再找存档**（见 [触发与叫停](触发与叫停.md) 第七节）。

## 五、收尾和留言

**每次都有反馈、都撤标签，由程序保证，不靠 agent 自觉**（2026-10-24 定）。收尾单独放在最后一个作业里，设成不管前面成功、失败还是被取消都会执行；它只看前面留下了什么（有没有改动、agent 有没有交汇报、是否超时或出错），按事实选留言模板，填进 agent 交的汇报。

**评论由程序按模板生成，agent 不直接写评论**（2026-10-26 定）。agent 只交一份固定字段的汇报（[agent 怎么干活](agent怎么干活.md)"submit"），程序校验、清洗后填进模板。所有评论末尾注明"本条由 AI 生成"，用 issue 的语言写。

**评论里写明依据的是哪一版**：固定写"按 某年某月某日某时 打上标签时的内容处理"，时间取打标签那条事件的时间；不附当时的原文，也不附哈希，因为 GitHub 对 issue 内容没有版本号或哈希，只记录每次修改的时间和修改人，能读仓库的人都能在正文的 **edited** 菜单里看到修改历史。处理期间标题或正文被改过时加一句提示：改的人是 Write、Maintain 或 Admin，就写明谁在什么时候改了什么，并说明如需按新内容处理请撤掉标签后重新打上；是其他人改的，只提示去看修改历史。

**各种结局：**

- **开出草稿 PR**：PR 描述里写 `Closes #编号`，issue 里汇报。
- **没有改动**（agent 判断做不了或不该做）：只在 issue 里留言说明为什么没改，不开 PR。
- **开工前检查没通过**：按模板说明没通过哪一条、缺什么，见 [接收哪些 issue](接收哪些issue.md) 第四节；修改人、图片的说明见 [agent 读到的内容](agent读到的内容.md)。
- **暂停**（2026-10-27 定）：例如

  > 已暂停：@某人 于 2026-10-27 10:30（UTC）撤掉了 agent-fix。进度保留到 2026-10-28 23:59（北京时间）。内容不改、在此之前重新打上 agent-fix 就从暂停处接着做；改过内容会从头开始。

  留言前先查撤标签之后有没有新的打标签：有，就不留这句，避免新运行已经开工了还出现一句过时的"已暂停"。删除和转移时 issue 已经不在，没法留言。
- **超时、出错**：说明原因，附运行链接。

**定时对账做兜底**（2026-10-24 定要做）：GitHub 偶尔根本没触发运行、或者收尾自己出错时，由一个定时运行的小工作流找出"挂着标签、却没有正在跑或排队的处理"的 issue，在 issue 里说明上次处理没有正常结束，并撤掉标签。要给最近刚打的标签留一段宽限时间，否则会把还在排队的运行误判成没人管。

## 六、监控（2026-10-27 定，10-30 补全）

要能实时看到运行过程，出事要有提醒；不自建任何服务。

- **结局和提醒放在 GitHub，必做**：agent 每走一步往运行日志打一行（Actions 页面实时滚动，延迟几秒）；结束时写作业摘要表、上传轨迹文件（和存档是同一份数据）；暂停、出错时由收尾作业在 issue 里留言。它不依赖网络，进程被强杀也不丢。GitHub 自己的运行结论分不出"暂停""交付失败"，我们的结局要写进摘要和轨迹文件。
- **过程的网页查看用 Langfuse 云服务免费档，可选**：配了密钥才开，没配照常跑；上传失败只打警告，不让收尾作业失败。和 LangSmith、Helicone、W&B Weave 的比较见 [调研/监控与运行轨迹](调研/监控与运行轨迹.md)。免费档的数据不能自动删除，试验项目可以接受。
- **Langfuse 由收尾作业在运行结束后一次性上传（2026-10-30 定）**：agent 跑的时候只往轨迹文件里记，不碰 Langfuse 密钥；收尾作业（不在 AWF 容器里、没有 agent）下载轨迹文件，拿密钥发给 Langfuse。原因：AWF 容器里 agent 的命令能读到主程序的环境变量，密钥放进主程序就可能被 issue 里藏的指令偷走。运行中的实时进度看 Actions 运行日志；Langfuse 在运行结束后一两分钟出现完整记录。被取消或超时的运行也要送上去，现在的工作流还做不到（第八节）。同一份轨迹重复上传是覆盖，不会多出一条。
- **Langfuse 里的记录格式（2026-10-30 定）**：发尽可能多的内容（每次调模型带完整对话，工具带完整输出），按 Langfuse 官方建议组织成"调模型、调工具穿插"的步骤，加上交付各步；凡是代码都配人话说明（退出码、结局、结束原因）；结局写进标签和分数。直接用 OpenTelemetry 发，以便填真实的开始时间。依据和细节见 [调研/Langfuse记录格式](调研/Langfuse记录格式.md)。
- **每次运行都要传上 Langfuse，不管结局如何（2026-11-03 定）**：交卷、出错、超时、到上限、被撤标签暂停、被取消，都要把已有的轨迹传上去。现在只有成功或失败时才上传 `agent-output`，被取消（含暂停）的情况还没接上，要和暂停存档一起做。
- **费用只记 token 和模型名，不折算成钱（2026-11-03 定）**：Langfuse 的价格表里没有 DeepSeek，DeepSeek 又分高峰、非高峰价，模型也还没最终定。
- **仪表盘要做（2026-11-03 定）**，放哪些图以后慢慢讨论。
- **不用 GitHub Pages 做实时监控**：它只能放静态页面，不能接收数据。

## 七、实现进度

已写，单元测试通过，还没在 GitHub 上实跑：

- [src/repoaegis/workdays.py](../src/repoaegis/workdays.py)：按工作日算暂停存档的截止时刻、产物的保留天数；节假日表 [src/repoaegis/calendars/cn.json](../src/repoaegis/calendars/cn.json) 目前只有 2026 年（照国办发明电〔2025〕7号录入），2027 年的通知发布后要补。
- [src/repoaegis/checkpoint.py](../src/repoaegis/checkpoint.py)：暂停存档的产物名。
- [src/repoaegis/precheck.py](../src/repoaegis/precheck.py)：记下最后一次打标签的时间（运行的身份）；停掉运行后等它完全结束；开工时挑出内容一致、没过截止时刻的最新一份暂停存档，把它所在的运行编号和产物编号交给后面的作业，其余暂停存档删掉。
- [src/repoaegis/langfuse_upload.py](../src/repoaegis/langfuse_upload.py)：收尾作业用它把轨迹文件上传到 Langfuse，只用标准库；轨迹文件的格式写在它开头的说明里，主循环（[loop.py](../src/repoaegis/loop.py)）照着写。结局分 8 种：已交卷、没有改动、已暂停、超时、达到上限、出错、交付失败、轨迹中途结束（例如程序被 AWF 的 65 分钟杀掉，没写结尾那一行）。2026-10-31 在测试仓库用一个只写仿真轨迹的 agent 替身实跑通过：AWF 容器里写出轨迹 → 产物 → 收尾作业上传 Langfuse。

还没写：agent 每步写进度、被取消时上传暂停存档、从存档恢复、各种留言、出错存档和完成记录的上传、定时对账。

## 八、待定

- **失败分类和重试**：各种失败怎么认定、哪些自动重试几次（建议交付失败重试 3 次，agent 失败不自动重来）；出错后重新打标签、内容一致时，要不要从出错存档接着做（建议不，只用来查原因）。交付能放心重试的前提是每一步都"先看再做"：分支推过就不再推，PR 已存在就不再开，评论写过就不再写。
- **定时对账**：多久一次。
- **各种留言的具体措辞**，以及汇报字段怎么填进模板。
- **收尾作业的运行条件（代码的缺口）。** 收尾作业现在只在 agent 作业跑过时才执行，开工前检查没通过时不会留言、撤标签（见 [触发与叫停](触发与叫停.md) 第九节）；agent 作业上传轨迹的步骤只在成功或失败时执行，被取消时收尾拿不到轨迹，Langfuse 也就收不到。两处都要改，收尾放在哪、怎么写条件，需你定。
- **密钥在哪一步遮、按什么规则遮。** `langfuse_upload.py` 的说明写由主循环写轨迹时遮（轨迹本身也是公开的产物），但 `loop.py` 还没做；规则没定。
- **结尾那行的结论现在是空的。** 轨迹格式要求 `run_end` 带一句给人看的结论，主循环现在不填。
- **Langfuse 记录格式和代码有两处不一样**：调研报告写退出码非 0 标红、分数是"步数和命令出错次数"，代码里退出码非 0 标黄、分数是"调用模型次数和工具出错次数"，是助手写代码时改的。以哪边为准，需你定。
- **摘要表的格式**还没定；每步日志和轨迹字段已经写在 `loop.py`、`langfuse_upload.py` 里。
- **待实测**：`if: cancelled()` 的步骤是否受"5 分钟后强制终止"的限制。
