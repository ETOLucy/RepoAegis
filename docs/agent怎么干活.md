# agent 怎么干活

> 这一篇管：开工以后，agent 用什么模型、怎么循环、手里有哪些工具、在哪份代码上改。每个工具的细节规则写在代码文件开头的说明里，这里只写要点；依据见文末各篇调研。agent 跑在什么沙箱里、密钥怎么藏，见 [安全设计](安全设计.md)。

## 一、模型和循环

- **只用一个模型，暂定 DeepSeek**（2026-10-27 定），通过它兼容 OpenAI 的接口调用。成本有限，不做多模型切换。
- **循环照 mini-swe-agent 的设计自己写，不把它当库引进来**（2026-10-25 定）：每一步把模型的回复交给工具执行，结果再交回模型，直到交卷。

调模型这一块（2026-11-02 定，代码 [src/repoaegis/model.py](../src/repoaegis/model.py)，依据见 [调研/调用DeepSeek](调研/调用DeepSeek.md)）：

- 只用 Python 自带的库直接发请求，不装 openai、litellm。地址和钥匙从 `OPENAI_BASE_URL`、`OPENAI_API_KEY` 读，在 Actions 上是 AWF 密钥代理的地址和占位钥匙。
- 默认 `deepseek-flash`、开思考、强度 high，写明在请求里；模型名可以用 `REPOAEGIS_MODEL` 换。三个都是暂定值，按成本和厂家默认选的，没有比较过效果。
- 用流式接收，两段内容之间超过 5 分钟没动静算卡住，这次运行剩下的时间用完也停。
- 临时故障最多重试 5 次，间隔 8 秒起翻倍到 64 秒；格式错、钥匙错、余额不足不重试。
- 模型的回答拼成一条带思考内容的消息，主循环原样存、原样发。用量原样交回，日志和 Langfuse 都显示 token，不显示钱；回答收得久时每 30 秒在日志里打一行进度。

循环怎么结束、设哪些上限（2026-10-31 定，依据见 [调研/循环结束上限与上下文](调研/循环结束上限与上下文.md) 第五节）：

- **怎么结束**：agent 第二次调用 `submit`、两次补丁完全一样时正常结束；回复里没有工具调用就打回，连续 3 次按出错结束。DeepSeek 不能强制调用工具，mini-swe-agent 也是这样处理的。
- **时间上限**：程序自己计时，累计 60 分钟就停；暂停后接着做也算在内，否则撤标签再打上就能绕过。AWF 的 65 分钟和作业的 80 分钟是兜底。
- **token 上限，不按钱算**：所有模型调用账单上的 token（输入含命中缓存的、输出含思考的）加起来不超过上限，往宽了设，可以配置。不按钱算是因为模型没定，DeepSeek 又分高峰和低峰价，Langfuse 也算不出 DeepSeek 的费用。
- **不设步数上限**：DeepSeek 在 mini-swe-agent 上成功的运行，中位数就要 79 步。
- **不做卡死检测**，只把重复调用记进运行记录。
- **到上限或出错**：不开 PR，留出错存档，由收尾作业在 issue 里说明原因。接口临时错误先重试几次。
- **上下文**：只截断单条过长的输出，不做遮蔽和摘要；真的超长就按出错结束。

代码里的几处细节（[src/repoaegis/loop.py](../src/repoaegis/loop.py)）：

- 时间和 token 上限只在每次调模型之前检查。最后一次回复要求的工具照样执行，这一步交卷就算交上。
- 每次调模型都告诉它这次运行还剩多少秒，模型那一层据此决定还能等多久、还能不能重试。
- 同一条回复里，交卷之后的工具调用不执行。
- 工具出错分两种：模型能自己改的（没有这个工具、参数不是 JSON、参数不对、命令超时），写成文字交回模型，标成出错；环境坏了（仓库目录不在、读 issue 服务连不上），整次运行按出错结束。
- 结局：时间到算超时，token 用满算到上限；连续不调工具、模型调用失败、对话超长、环境坏了算出错；交卷时补丁为空算"没有改动"。

## 二、工具（2026-10-25 定，10-27 补全）

一共四个：`bash`、`str_replace_editor`、`read_issue_ref`、`submit`，代码在 [src/repoaegis/tools/](../src/repoaegis/tools/)。不给专用的搜索、计划、思考、上网、查 git 历史、看其他分支的工具。

**不设单独的停止工具。** agent 发现做不了或不该做时，不改代码直接交卷，在汇报里写明为什么没改；程序看到没有改动，就在 issue 里留言说明，不开 PR（2026-10-30 确认）。

### bash：执行命令

- 每条命令单独开一个 bash 进程，在仓库根目录执行；`cd`、`export` 不会留到下一条（照 mini-swe-agent）。
- **不设命令黑白名单**，安全靠沙箱和发布前的产出检查（2026-10-26 定）。没有一家官方项目用命令名单做安全边界。
- 超时默认 120 秒，agent 可以调大，最多 600 秒（照 Claude Code）。命令结束或超时后，把它启动的进程一起杀掉。命令没有标准输入。
- 退出码不为 0 不算出错，照常把输出交回；超时算出错。
- 输出超过 1 万字符时只给开头 5000、结尾 5000（照 mini-swe-agent），全文留在文件里，把路径告诉模型（照 OpenHands）。
- **命令只看到白名单里的环境变量**（2026-10-27 定，10-30 加证书变量）：从主程序的环境里只抄找命令、家目录、用户名、临时目录、AWF 的出网代理和证书文件这几类，另外写死"不分页、不上色、不画进度条、用 UTF-8"和 `CI=true`。变量名里含 `KEY`、`SECRET`、`TOKEN`、`PASSWORD`、`CREDENTIAL` 的出现了就报错、不开工，不悄悄删。见 [src/repoaegis/sandbox/env.py](../src/repoaegis/sandbox/env.py)。这一层只防 `env` 之类的命令直接看到变量，挡不住读主程序启动时的环境，所以主程序里本来就不放真密钥。

### str_replace_editor：看文件、改文件（2026-10-27 定）

- 四个命令：查看、新建、替换、插入。没有撤销，要退回就用 bash 里的 git。
- 路径必须是绝对路径，解析掉 `..` 和符号链接后必须在仓库目录之内；任何一层的 `.git/` 和顶层的 `.github/` 只能看不能改。列目录时不顺着符号链接往下走。
- **改之前必须用编辑器看过**，看过之后被别的东西改过就要重看；编辑器自己改的不用重看，bash `cat` 不算（照 Claude Code）。
- 替换时原文必须完全一致、只出现一次。不动制表符；文件用 `\r\n` 换行时，把模型给的文字也换成 `\r\n`。
- **Python 文件改完检查一遍**（照 SWE-agent 论文里那版）：用 flake8 只查语法、缩进、未定义名字等几条，改前改后各查一次，这次修改新增了错误就撤回，把错误和原文交给模型重改。新建 `.py` 文件时只查一次，有任何错误就不建。
- 只改 UTF-8 文本文件；二进制文件和超过 10 MB 的不看也不改。新建时文件已存在、父目录不存在都报错。
- 查看超过 16000 字符就截断，提示先用 `grep -n` 找行号。发给模型的文字用英文。

依据和其余细节：[调研/编辑器的细节](调研/编辑器的细节.md) 第五节。

### read_issue_ref：读本仓库的其他 issue（2026-11-01 改为按需读，11-02 定细节）

agent 没有令牌，网络也受限。想读哪篇 issue，这个工具就把编号经 AWF 的代理交给运行机上的读 issue 服务，服务当场向 GitHub 读、把关、清洗后交回。规则见 [agent 读到的内容](agent读到的内容.md) 第五节，代码 [read_issue_ref.py](../src/repoaegis/tools/read_issue_ref.py)、[issue_service.py](../src/repoaegis/issue_service.py)。

- 参数：整数 `number`；可选的 `offset`，长正文从第几个字符读起。能读本仓库任意一篇，不限篇数、不限层数。
- 读得到：返回标题、状态和正文，和第一条消息里的 issue 一样包在 `<issue>` 标签里。正文是打标签那一刻的版本，状态是现在的。
- 正文超过 16000 字符时分段给，每段末尾写明下一段的 `offset`。
- 读不到：说明原因（是 PR、找不到、打标签后才建的、修改人没有写权限、正文被删），GitHub 出错时把它的原因交回，都标成出错。读正在处理的这一篇，直接拒绝（它已经在第一条消息里）。
- 服务连不上或回答看不懂：算环境坏了，按出错结束这次运行。

### submit：交卷（2026-10-30 定）

- **要调用两次才算交上**（照 SWE-agent）。第一次：程序把仓库里的全部改动生成补丁，连同复查清单发回模型，并用产出检查的规则先查一遍，有问题一并提醒。第二次：补丁和第一次完全一样才算交卷，不一样就当作新的第一次。
- **补丁由程序生成**，不信 agent 自己说改了什么：和开工时的提交比，含新文件，agent 自己用 git 提交过的也算。被 `.gitignore` 忽略的文件一般不进补丁，但 agent 用 `git add -f` 强行加入或删掉 `.gitignore` 里那一行，照样会进来（2026-10-30 实测），要靠产出检查拦下（[安全设计](安全设计.md)"待定"）。用一份临时暂存区生成，不动 agent 自己的；生成时关掉 git 的 fsmonitor、外部 diff 程序和 textconv，环境变量用白名单，免得 agent 改了 git 配置、借交卷执行命令。
- **复查清单**：测试重跑过没有；临时脚本、调试输出删了没有；有没有和 issue 无关的改动；假设和跳过的要求写全了没有。
- **汇报五个字段**：`title`（PR 标题）、`summary`（改了什么、为什么；没改时写为什么没改）、`testing`（怎么验证的）、`assumptions`（自己补上的假设）、`skipped_requests`（issue 里没照做的要求和原因）。用 issue 的语言写。`Closes #编号`、AI 生成说明、按哪个时间的版本处理等固定内容由程序加。
- **不按改动行数拦**：100 行只是挑 issue 时的软限制。
- 汇报字段填错会报错交回模型改，不算一次调用。交卷后补丁和汇报写进仓库外的输出目录，主循环看到就结束；再调用 submit 一律拒绝。
- 两次调用这套做法以后要单独评测（2026-10-30 定）。

依据：[调研/交卷工具](调研/交卷工具.md) 第五节。

## 三、在哪份代码上改

### 克隆到哪、取哪个提交（2026-10-25 定）

运行机上有两份代码，分开放：

- **要修的仓库**放进 `target/` 子文件夹，在克隆那一刻取默认分支的最新提交，深度 1，克隆后不留令牌（`persist-credentials: false`）。
- **RepoAegis 自己的代码**用 `actions/checkout` 检出到 `repoaegis/` 子文件夹，按 `job.workflow_sha` 取工作流文件所在的那次提交，保证一次运行从头到尾只用一个版本；不用 `pip install` 来拿。RepoAegis 用自己单独的虚拟环境，agent 部分要用的第三方库在确定开工以后再装；开工前检查只用 Python 自带的库。

### 浅克隆，不给查历史和看其他分支的工具（2026-10-24 定）

规则是：只有找到"带历史能让 agent 做得更好"的数据，才用完整克隆。没有找到直接比较两者解决率的数据；找到的正面数据测的都是"框架专门做的查提交工具"或"框架先查好历史再塞给模型"，而且 agent 很少主动查历史（SWE-bench 维护者在约 10000 条运行记录里只找到 5 条用了 `git log`）。所以用浅克隆，深度 1。

- **提示词里要写明仓库没有历史。** 浅克隆下 `git blame` 不报错，而是把所有旧行都算到最新那个提交头上（实测 389 行全部显示为最新提交），所以要告诉 agent 不要用 `git log`、`git blame` 判断代码的来历。
- 不用 `--filter=blob:none`：实测克隆只省一点，跑 blame 时却要逐个联网下载旧文件，同一条 blame 从 0.013 秒变成 1 分 47 秒。
- **"查提交"的工具现在不做**，留作以后的选项：等在真实仓库上看到 agent 确实因为缺历史而做错再加。要做的话，仍然浅克隆，由外层程序替它 `git fetch --deepen=N` 补历史再搜索。
- **看其他分支的工具不做。** 所有官方项目都只在默认分支上开工；issue 明确说问题只出在别的分支上时，开工前的检查判为不处理（[接收哪些 issue](接收哪些issue.md) 第五节）。
- **以后做评测时**：浅克隆到修复前的那个提交天然不会看到"未来"的提交；如果改成带历史，必须照 SWE-bench 的 `git_clone_timesafe()` 删掉未来的提交和标签。

## 四、待定

- token 上限的默认值：代码里暂填 2000 万，要在测试仓库实测一次运行用多少 token 再定，往宽了设。
- **最后一条命令可能越过 AWF 的 65 分钟（代码的缺口）。** 时间上限只在调模型前检查，而 bash 单条命令最长 600 秒，接近 60 分钟时启动的命令会跑过 AWF 的 65 分钟，程序被杀，轨迹里没有结尾那一行。助手建议让 bash 超时不超过这次运行剩下的时间，需你定。
- 模型的回答被截断（结束原因 `length`）或被内容过滤（`content_filter`）时怎么办：现在只记下原因，截断的回答会被当成"没调工具"打回。需你定。
- **编辑器要的 flake8 没装（代码的缺口）。** agent 作业从没装过 RepoAegis 的依赖，编辑器第一次检查 Python 文件就会报错，整次按出错结束。用什么方式装，需你定。
- 第一条消息的组装已写（[src/repoaegis/first_message.py](../src/repoaegis/first_message.py)），规则见 [agent 读到的内容](agent读到的内容.md) 第八节；还没接进主循环和工作流。
- 检查作业和 agent 作业各自克隆一次，中间有人推了代码，两边看到的就不一样。建议检查作业记下提交号，agent 作业按它克隆，待讨论。
- 编辑器的写法和 DeepSeek 的实际表现，等真实代码跑起来后在测试仓库里验证。对 DeepSeek 来说只给 bash 也可能够用，没有数据。
- 用户项目的依赖怎么装、网络白名单放哪些网址，和沙箱一起定。
