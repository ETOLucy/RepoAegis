# 调研报告：str_replace_editor 的细节

> 调研日期：2026-10-27。源码和文档都是本次打开的原文，位置写在每条后面。标"推断"的是从源码推出来的，原文没有直说。

## 一、为什么查

2026-10-25 定了给 agent 一个编辑器工具（带行号查看、新建、唯一字符串替换、插入，绝对路径，拒绝修改受保护文件），细节约定"写到这块代码时再查"（见 [agent工具清单](agent工具清单.md) 第八节）。现在要写了，逐项看官方项目怎么做。

## 二、方法和出处

- SWE-agent：`SWE-agent/SWE-agent` 主分支 `tools/edit_anthropic/bin/str_replace_editor`（712 行）和同目录 `config.yaml`。这是它默认配置 `config/default.yaml` 装的编辑器。
- OpenHands 新版 SDK：`OpenHands/software-agent-sdk` 主分支 `openhands-tools/openhands/tools/file_editor/` 下的 `editor.py`（840 行）、`utils/constants.py`、`utils/config.py`。
- Anthropic 官方文本编辑器工具文档：platform.claude.com/docs/en/agents-and-tools/tool-use/text-editor-tool（命令说明、"Implement the text editor tool"、"Change log" 三节）。
- Claude Code 的 Edit 工具：以本会话里 Claude Code 自带的工具说明为准（"编辑前必须先读过"、`replace_all` 选项）。

## 三、各家做法

**有哪些命令。** SWE-agent 和 OpenHands 都是 view、create、str_replace、insert、undo_edit 五个（SWE-agent `config.yaml` 的 `enum`；OpenHands `editor.py` 第 120–154 行）。Anthropic 文档的更新记录写明：2025-04-29 给 Claude 4 出的 `text_editor_20250429` "removes the `undo_edit` command"，现行版本只有 view、str_replace、create、insert 四个；原因没写（Change log 一节）。

**路径。** 三家都要求绝对路径。SWE-agent 遇到相对路径会报错，并提示"你是不是想写 某某绝对路径"（`validate_path`，第 406–416 行）；OpenHands 同样（`editor.py` 第 629–642 行）。路径不存在（create 除外）、对文件夹用了查看以外的命令，都报错。Anthropic 文档的实现建议里写了"校验路径，防止目录穿越"和"改之前先备份"（"Implement security measures" 一步）。

**查看文件。** SWE-agent 按 `cat -n` 的格式输出：行号占 6 位，后接制表符（`_make_output`）。超过 16000 字符就截断，并附一句提示：先用 `grep -n` 找到行号，再用 view_range 看（第 27–28 行）。OpenHands 也是 16000（`utils/constants.py`），对 view_range 越界的处理更宽松：结束行超出文件长度时自动收到最后一行，并加一句提醒（第 397–423 行）；SWE-agent 遇到越界直接报错（第 460–480 行）。Anthropic 的 view_range 用 -1 表示"读到文件末尾"，并给出可选的截断长度参数 `max_characters`，示例值是 10000。

**查看文件夹。** SWE-agent 运行 `find 路径 -maxdepth 2 -not -path '*/\.*'`，列出两层、不含隐藏文件（第 446–455 行）。OpenHands 也是两层不含隐藏，另外告诉模型"这个目录里有几个隐藏项"（第 289–316 行），过长时截断并建议改用 `ls -la`。

**二进制文件和大文件。** OpenHands 用第三方库 `binaryornot` 判断二进制，遇到就拒绝查看；文件超过 10 MB 也拒绝（第 11、68 行）。SWE-agent 没有专门判断。

**编码。** SWE-agent 依次尝试系统默认编码、UTF-8、latin-1，最后用"坏字节换成替换符"的 UTF-8 读，写回时沿用读成功的那种编码（`read_file`、`write_file`）。OpenHands 有单独的编码检测模块 `utils/encoding.py`（226 行，本次没细读）。

**制表符。** SWE-agent 在 str_replace 和 insert 时，对**整个文件**调用 `expandtabs()`，把所有制表符换成空格后再写回（第 519–521、598–599 行）。推断：一个用制表符缩进的文件（Go、Makefile）只要被它改一处，整个文件的缩进都会变，Makefile 还会因此失效，diff 也会变成整个文件。OpenHands 的 `editor.py` 里没有 `expandtabs`。

**替换。** 两家都要求原文在文件里**恰好出现一次**：找不到就报错，出现多次就报错并列出所在行号（SWE-agent 第 516–534 行；OpenHands 第 204–243 行）。不同点有三：OpenHands 找不到时会把原文首尾空白去掉再找一次（第 214–236 行）；SWE-agent 遇到原文和新文本相同时直接报错（第 536–538 行）；Claude Code 的 Edit 工具有"全部替换"选项，并要求改文件之前先读过它。替换成功后，两家都返回改动处上下各 4 行、带行号的片段（SWE-agent `SNIPPET_LINES = 4`；OpenHands `SNIPPET_CONTEXT_WINDOW = 4`）。

**插入。** `insert_line` 表示插在第几行之后，0 表示插到文件开头，超出范围就报错（SWE-agent 第 596–615 行；Anthropic 文档 insert 一节）。

**新建。** 文件已存在时，两家都拒绝新建，不覆盖（SWE-agent 第 421–423 行；OpenHands 第 649 行）。父目录不存在时，SWE-agent 报错，要求先建目录（第 431–433 行）。

**改完自动检查语法。** SWE-agent 的编辑器能在修改前后各跑一次 flake8，只报告新增的错误，但改动照样生效（第 33、540–575 行）。这个功能默认**关闭**（`USE_LINTER` 默认为 false），而且只对 Python 文件有用。SWE-agent 论文里"编辑后不做语法检查"从 18.0% 掉到 15.0% 的数据，测的是它旧版的窗口式编辑器，不是这个编辑器。

**撤销。** SWE-agent 和 OpenHands 都为每个文件保存修改前的版本（OpenHands 每个文件最多存 10 个，`editor.py` 第 88 行），undo_edit 退回上一版。

## 四、借鉴什么，不借鉴什么

- **借鉴三家都有的部分。** 绝对路径；替换时原文必须恰好出现一次，出现多次就列出行号；替换后返回上下 4 行的片段；插入的行号含义；新建时不覆盖已有文件；文件夹列两层、不含隐藏文件。这些在三家之间一致，又有长期使用作依据。
- **借鉴 OpenHands 的细节。** view_range 结束行越界时自动收到最后一行并提醒，省掉模型一步；文件夹视图告诉模型有几个隐藏项；拒绝查看二进制文件和超大文件，二进制的判断用标准库自己写，不引入 `binaryornot`。
- **不借鉴 SWE-agent 的 expandtabs。** 它会悄悄改掉整个文件的缩进。
- **不借鉴撤销。** Anthropic 在 Claude 4 版本里删掉了撤销（原因没写）。仓库本来就是 git 仓库，用 bash 跑 `git diff`、`git checkout -- 文件` 就能看和退。
- **不借鉴改完自动检查语法。** SWE-agent 自己默认关着，而且只管 Python；agent 可以自己跑测试。
- **不借鉴"全部替换"和"必须先看过才能改"。** 我们的任务小，"恰好出现一次"已经能防止改错位置；"先看过"要额外记录状态。（这两条后来被 2026-10-27 的答复改掉：改完要检查、必须先看过才能改，见第五节。）
- **不借鉴"找不到就去掉首尾空白再找"。** Anthropic 文档要求原文完全一致，包括空白和缩进；放宽匹配会让模型对空白越来越随意。

## 五、建议与决定

2026-10-27 用户的答复：第 1 条确认，撤销就是用 git 的记录退回；第 3 条按 Anthropic 的写法，-1 表示读到末尾；第 9 条改为父目录不存在就报错，让模型先建目录（照 SWE-agent）；第 10 条改为**改完要检查**、**必须先看过才能改**，"全部替换"仍不做；其余按建议。同日补定：改完检查照 SWE-agent 论文里那版（`tools/windowed_edit_linting/bin/edit`）：用 flake8 只查 `F821,F822,F831,E111,E112,E113,E999,E902` 这几条（取自 `edit_anthropic` 编辑器源码第 186 行的默认值），改前改后各查一次，修改新增了错误就撤回，把错误和原文交给模型重改，只管 Python 文件；"先看过"照 Claude Code：用编辑器看过（整份或一段都算），之后文件被别的东西改过就要重看，编辑器自己改的不用重看，bash `cat` 不算；发给模型的文字用英文。第 4 条（文件夹视图告诉模型隐藏项个数）维持建议。

1. 命令：view、create、str_replace、insert 四个，不要撤销。
2. 路径：必须是绝对路径，而且在仓库目录之内（先解析掉 `..` 和符号链接，再判断）；`.git/` 和 `.github/` 里的文件能看不能改。
3. 查看文件：`cat -n` 格式；view_range 的结束行写 -1 表示读到末尾，越界时自动收到最后一行并提醒；超过 16000 字符截断，并提示先用 `grep -n` 找行号。
4. 查看文件夹：两层，不含隐藏项，告诉模型有几个隐藏项。
5. 拒绝查看和修改二进制文件（开头 8000 字节里有空字节就算），以及超过 10 MB 的文件。
6. 只处理 UTF-8 文件，不是 UTF-8 的拒绝修改，提示用 bash。
7. 不动制表符；换行符保持原样：文件用 `\r\n`，就把模型给的文本也转成 `\r\n` 再匹配、再写回。
8. 替换：原文必须恰好出现一次，不去掉空白重试；原文和新文本相同时报错；新文本为空表示删除；成功后返回改动处上下 4 行。
9. 新建：文件已存在就拒绝；父目录不存在就自动建好（仍限于仓库之内）。（已按答复改为父目录不存在就报错。）
10. 不做改完自动检查语法，不要求先看过才能改，没有"全部替换"。（已按答复改为改完要检查、必须先看过；"全部替换"仍不做。）
11. 所有拒绝都标成出错（`error=True`），写成文字交回模型。

**写代码时补查（2026-10-27）。** SWE-agent 判断"新增错误"的办法（`format_flake8_output` 和 `_update_previous_errors`，第 100–178 行）：修改前就有的错误，按改动增减的行数挪到新行号，挪完还对得上的不算；落在被改那几行里的旧错误不作数；改动位置上方的错误也不算。我们照这个做，但改了一处：它算被改范围时用的是**新文本**的行数（第 563–566 行），而挪行号用的是"新行数减被改范围行数"，两者相同，增减的行数总是 0（推断）。我们把"原文占几行"和"行号挪了多少（新旧文本换行数之差）"分开算。flake8 用 `--isolated`（不读仓库自己的 flake8 配置），用 RepoAegis 自己虚拟环境里的 Python 运行，不依赖被改仓库的环境；版本固定为 7.4.1（PyPI 显示 2026-09-23 发布）。

## 六、尚未查清
