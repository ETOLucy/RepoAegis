# 调研：一次运行在 Langfuse 里怎么记，才方便复查问题

读取和实测日期：2026-10-30。Langfuse 云服务日本区，Python 库 langfuse 5.0.4、OpenTelemetry 1.45.1。

## 为什么查

监控已定为：运行结束后由收尾作业读轨迹文件，一次性上传 Langfuse（见 [暂停存档与监控](../暂停存档与监控.md) 的"监控"一节）。用户的要求是：**尽可能多地发内容**，并且让使用者打开一条记录就能看到尽量多、又清楚的信息，方便复查问题；**凡是代码（退出码、结局代号等）都要写出它是什么意思**，不能只给一串代码。

Langfuse 的网页界面我们改不了，能决定的是数据怎么组织——它按数据的形状决定怎么显示。所以要查：它认什么形状、能收多大、事后上传怎么填真实时间。

## 方法和标注

- 读 Langfuse 文档页面（网页抓取），读 Langfuse 主仓库和 `langfuse/codex-observability-plugin` 的源码（`gh api`），读本机装的 langfuse 5.0.4 源码。
- 往自己的 Langfuse 项目发了三条仿真运行，再用接口查回来。内容全是编的。
- 【原文】= 打开了一手来源；【实测】= 在本机或 Langfuse 云上跑过；【推断】= 根据前两者推出来的；【待验证】= 没查到或没测。

## 数据

### Langfuse 认什么形状

- 官方"好的记录长什么样"页面：每次调模型记一条 `generation`，每次工具调用记一条 `tool`，两者按时间穿插、挂在同一个上级下面，不要把整个循环包成一条；思考过程记在 generation 上；名字要固定、少而稳定（比如 `call-model`），每次不同的值放 metadata；模型输入用 OpenAI 消息格式，工具调用放在 assistant 消息的 `tool_calls` 里、参数写成 JSON 字符串、和结果用同一个编号对应，这样才显示成对话气泡和工具卡片；整条记录的输入输出取自最上层那一步，会显示在列表里；标签要在创建时设好，之后改不了；多条记录带同一个 `session_id` 会合并成会话视图，后面的模型调用要带上前面的完整对话才能连起来。【原文：https://langfuse.com/docs/observability/best-practices】
- 只要有一步的类型不是 `span`、`event`、`generation`（比如 `agent`、`tool`），网页就按时间和层级自动画 agent 流程图；"合并"视图里同名步骤并成一个节点、循环画成环。【原文：https://langfuse.com/docs/observability/features/agent-graphs】
- 会话视图 2026-10-13 改版：跨记录连成一段对话，侧栏可跳到每次工具调用；会话列表可按"可用工具""调用过的工具"筛选。【原文：https://langfuse.com/changelog/2026-10-13-redesigned-session-view】
- 免费档包含自定义仪表盘。【搜索结果转述 https://langfuse.com/pricing ，未逐字核对】

### 能收多大

- 官方文档没有列出上限。【原文：未找到】
- 源码：旧的接收接口每次请求最多 4.5MB（`web/src/pages/api/public/ingestion.ts` 第 59–60 行）；OpenTelemetry 接收接口的上限由 `LANGFUSE_OTEL_INGESTION_MAX_BODY_BYTES` 决定，自建默认 512MB（`web/src/env.mjs` 第 667–671 行），超过 16MB 记一条警告（`web/src/server/otel/processOtelIngestion.ts` 第 42 行）。云服务实际设的值查不到。【原文】
- 显示：超过 15 万字符的内容改用纯文本显示，不再按 Markdown 排版（自建默认值 `LANGFUSE_MARKDOWN_RENDER_CHARACTER_LIMIT`）。【原文：https://langfuse.com/self-hosting/configuration】云服务的值【待验证】。
- 社区有人报告内容在 1MB 处被截断（langfuse/langfuse issue #4940、讨论 #7374），是自建版或旧接口。【原文，未复现】
- **实测（云服务）**：一条工具输出约 205 万字符、之后每次调模型的输入也各约 207 万字符，整条运行约 10MB，一次发出；15 条全部收到，每块内容长度和发出时一字不差。【实测】

### 事后上传怎么填真实时间

- Python 库 5.0.4 的公开接口只能指定结束时间（`_client/span.py` 第 415 行 `end(end_time=...)`），开始时间只有内部的 `_otel_tracer` 能设。【原文】
- 官方 Codex 插件是 JS 写的，JS 库可以传 `startTime`。【原文：`plugins/tracing/src/trace.ts` 第 509–511、553–556 行】
- **实测**：不用 Langfuse 库，直接用 OpenTelemetry 的发送器发到 `{地址}/api/public/otel/v1/traces`（Basic 认证，用户名公钥、密码私钥），每一步用 `start_span(start_time=...)` 和 `end(end_time=...)` 填时间，属性名照 Langfuse 库自己用的那套（`_client/attributes.py` 第 30–57 行，如 `langfuse.observation.type`、`langfuse.observation.input`、`session.id`）。故意把运行时间设在 10 分钟前，查回来的时间都对；约 10MB 用 1.7 秒发完，发完约 10 秒能查到。【实测】
- 结局、步数等分数用 Langfuse 库的 `create_score` 补打，能写中文名、中文取值和说明。【实测】

### 官方 Codex 插件怎么做

- 在 Codex 每轮结束时由钩子读本地会话记录，事后上传——和我们的第 3 种做法一样。【原文：README 第 15–25 行；`trace.ts`】
- 每轮一条 `agent`，每次调模型一条 generation（输入是系统提示加对话，附工具定义；输出含回复、思考、工具调用；token 含思考数），每次工具调用一条 `tool`（参数、输出、出错时标 ERROR 并写出错信息、调用编号放 metadata）。【原文：`trace.ts` 第 260–300、476–560、610–621 行】
- 每次调模型附的对话默认最多 20 万字符（`max_history_chars`）。【原文：`config.ts` 第 44 行】
- 不做脱敏，README 第 72 行提醒"所有内容都会上传"。【原文】

## 借鉴什么、不借鉴什么

- **官方最佳实践页：全部照做。** 步骤类型、穿插方式、消息格式、固定名字、会话分组都按它来，网页才会显示成对话、卡片和流程图。
- **Codex 插件：借鉴"事后上传"和每步记什么。** 不借鉴 20 万字符的对话上限（用户要尽可能多，实测 2MB 一块也收得下）；不借鉴"不脱敏"（我们在写轨迹文件时就遮密钥）。
- **Langfuse Python 库：只用来补打分数和查数据，不用它发步骤。** 它的公开接口填不了开始时间；直接用 OpenTelemetry 发，属性名照它的来。

## 结论（2026-10-30 用户确认"就按这个"）

一次 Actions 运行在 Langfuse 里是一条记录，组织如下。所有代码旁边都写人话说明。

**整条记录**
- 名字固定为 `agent-fix`。输入：issue 的标题、正文、链接。输出：一段给人看的结论（结局、PR 链接、改动、测试结果、步数、出错次数、用时）。
- 附加信息：仓库、issue 链接、打标签的人和时间、Actions 运行链接、起点提交、RepoAegis 版本、模型、上限设置、结局说明。
- 标签写结局，如"结局：已交卷"，可在列表里筛选。
- 分数：结局（分类）、步数、命令出错次数，每个带一句说明。
- 同一个 issue 同一次打标签产生的几次运行（暂停后接着跑）用同一个会话编号，写成"仓库#编号 打标签于 时间"。
- 环境：测试仓库用 `sandbox`。

**每次调模型（`call-model`，类型 generation）**
- 输入：完整对话加可用工具列表，不设上限。输出：回复、思考过程、要调的工具。
- token 分四项：未命中缓存的输入、命中缓存的输入、输出、思考。
- 附加：第几步、结束原因（如"tool_calls（模型要调用工具）"）、重试次数；开始出字的时间。

**每次工具调用（名字就是工具名，类型 tool）**
- 输入：参数。输出：完整输出（给模型看的被截断时注明"这里记的是完整输出"）。
- 附加：第几步、调用编号、用时、退出码及含义（如"4（pytest 用法错误，常见原因是测试文件路径不存在）"）；改文件时附改动前后的差异。
- 退出码非 0 标为出错，红字写"命令以退出码 N 结束：含义"。

**交付（`deliver`）**：推送分支、开 PR、在 issue 留言、撤标签，每步记结果和链接；输入是最终补丁。

**每次运行大约用多少计费单位**【推断】：每步 2 条，加交付 5 条、整条 1 条、分数 3 个。50 步的运行约 109 单位，免费档每月 5 万单位约够 450 次这样的运行。

## 尚未查清的

- 云服务对 OpenTelemetry 请求体和单条内容的实际上限（实测 10MB 一次没问题，更大的没测）；超过 15 万字符改纯文本显示，在云服务上是否也是这个值。
- 退出码含义表：目前只有通用的几个和 pytest 的 0–5，别的程序（npm、go test 等）要随用随补，查不到的写"含义取决于具体程序"。
- 仪表盘放哪些图（每天运行次数、各结局占比、token 趋势等），等数据格式落地后再配；免费档仪表盘的具体限制待核对。
- 密钥遮挡：在写轨迹文件时就做，具体规则另定。
- 网页上的实际显示效果（对话气泡、工具卡片、流程图、会话视图）没有截图存档，以上只查回了数据本身。
